# Vandi - the altar, the stars, and who the kill belongs to.
#
# It brings its own altar. `location Eikthyrnir` spawns a real Eikthyr altar in front of you
# through the game's own test-spawn call, and it is gone on the next load, so stand anywhere
# with a little open ground ahead - the Meadows is simplest.
#
# Everything here needs the real summoning path, because that is what the mod hooks: the
# offering says who made it, the altar's owner reads that when the boss appears, and the kill is
# credited off the stamp on the creature. Spawning Eikthyr with the scenario's own spawn step
# would test the spawn step. So the trophies go in through `offer`, which is
# OfferingBowl.UseItem - the call the hotbar makes, and the one that reaches InitiateSpawnBoss.
#
# The first draft of this file used `goto` and `use` on the altar, failed at step 6 on its first
# run on 2026-09-24, and could never have passed: both steps search building pieces, an altar is
# part of a location and not a piece, and pressing E on this kind of altar does nothing anyway.
#
# The first `keyis` below is also the step that catches the bug fixed on 2026-09-28. Until then
# the kill was checked for ownership after OnDeath had already let go of the boss's ZDO, so no
# machine counted it, and that step would have read "not set at all" even with the altar working.
#
# What it proves, in order: a boss summoned with nothing on the record arrives plain, the kill
# is credited to the summoner, and the next one arrives with a star because of it.

clear
god
ghost

# A clean record for this character. The scenario owns this key for the length of the run.
unkey vandi_p_$player_defeated_eikthyr
wait 1

# Eikthyrnir, the location's name since before 1.0. The first run asked for Eikthyrnest,
# which does not exist, and TestSpawnLocation refuses an unknown name without a word -
# Devkit's `location` step now lists the names it does know when that happens.
location Eikthyrnir
wait 3

# No Eikthyr but the ones this run summons. A run that stops halfway leaves its boss standing
# for the rest of the session, stamped and starred, and `level` and `kill` take the nearest
# Eikthyr they find: the run on 2026-09-28 left a one star Eikthyr beside its altar, and a
# second run in that session and that spot would have measured it instead of its own.
banish Eikthyr 80
give TrophyDeer:2
wait 1

# The offering, and twenty seconds for the boss. The first run on 2026-09-28 waited nine, on the
# strength of m_spawnBossDelay's 5 in code, and that is not what this altar carries. Nothing was
# there at nine seconds; the boss from that offering was the one the second `level` then found,
# still plain, and when it was killed the kill was credited as it should be. The second
# offering's boss arrived only after that kill had been recorded, and Vandi's log shows it
# coming at one star for one kill. So the altar's delay is more than nine seconds plus a death
# animation, and at most the thirteen seconds between the two offerings, because the altar
# ignores an offering while its last boss is still on the way and this one did summon. Utangard's
# altar scenario saw the same that day: no Eikthyr within 80 m eight seconds after an offering.
offer TrophyDeer
wait 20

# Never killed him, so he is exactly the boss the game makes.
level Eikthyr 1

kill Eikthyr
wait 3

# The credit. This is the whole point of the mod: it went to the character that paid for the
# offering, and it is one, not two.
keyis vandi_p_$player_defeated_eikthyr 1

# And again, which is where the record starts to cost something. One previous kill is one
# star, and one star is level 2.
give TrophyDeer:2
wait 1
offer TrophyDeer
wait 20
level Eikthyr 2

kill Eikthyr
wait 3
keyis vandi_p_$player_defeated_eikthyr 2

unkey vandi_p_$player_defeated_eikthyr
